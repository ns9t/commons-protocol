# Working Notes — Commons Protocol
### Internal only — not for publication

## Open flags

**Flag 1 — Section title "One Movement"**
Currently used. Alternative "The Movement" considered and set aside as potentially too generic or politically coded. Review on next pass.

**Flag 2 — Hawken placement**
Moved from introduction to "One Movement" section body and footnote. Introduction now opens with the document's own argument. Review whether current placement still feels too prominent.

**Flag 3 — Question curation governance**
The pyramid model is described but not governed in detail. Needs a dedicated design document addressing: who makes elevation determinations, how gaming is detected, how appeals work, how capture by well-resourced groups is prevented.

**Flag 4 — Interactive globe / interconnection map**
Needs a dedicated design document. Key questions: data sources, currency, independence of editorial decisions about which connections are displayed.

**Flag 5 — Blockchain / token layer**
Architecturally separate from signal layer. ATPcoin concept remains valid as ecosystem funding mechanism. Must never attach to the vote itself. Requires its own design document.

**Flag 6 — Naming**
Unresolved. Full candidate list: Earth Commons Grid, Earth Resonance Grid, Earth Resonance Project, Conscience Earth Grid, Global Conscience Grid, Common Ground Protocol, Commons Signal Grid, Commons Layer, Earth Grid, Earthsignal. Strongest current candidates: Common Ground Protocol, Earth Commons Grid. Decision deferred until document is stable.

**Flag 7 — Publication timing**
Internal development only until verification, governance, and interconnection map have provisional design answers.

**Flag 8 — Stewardship identity**
Decision pending: pseudonymous steward from outset (better for institutional relationships) vs. anonymous circulation until organic stewardship group forms (more consistent with philosophy). No institutional approaches (Hawken / Drawdown / Consul Project) until document reaches a version that can stand on its own.

**Flag 9 — Forking clarification**
Now explicit in stewardship section. Founding document is not forkable — it is the constitution. Implementations branch from it. Invitation section now calls for collaboration on a single first build rather than independent implementations.

**Flag 10 — Next design documents needed**
In rough priority order:
1. Governance design — question elevation process
2. Verification design — human identity without centralised database
3. Interconnection map — data sources and editorial governance
4. Token / funding layer — separate from signal, ATP model basis

**Flag 11 — Institutional relationships**
Natural first contacts once document is stable: Project Drawdown, Consul Project, Fediverse / ActivityPub community, Nostr developer community. Warm introduction preferred over cold approach in all cases.
