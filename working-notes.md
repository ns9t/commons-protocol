## Active flags — design tensions

**Flag 54 — Updraft as infrastructure funding: legitimate use case or spirit violation?**
Does not violate founding document as written. Sits in tension with ATP model's spirit — Updraft's UPD token has speculative market exposure that the CEU model explicitly avoids. Working position: Updraft as provisional infrastructure funding while protocol establishes itself, with explicit intention of transitioning to CEU model as community develops. Key unresolved question for Adam: how does Updraft handle UPD token price collapse? What is the resilience model?

**Flag 55 — The Wikipedia governance / output tension**
Wikipedia cited as governance prior art but its outputs in contested domains are demonstrably compromised. The distinction between borrowing governance mechanisms vs epistemic outputs is technically valid but blurrier than the design documents imply. Use Wikipedia as cautionary model as much as exemplary one.

**Flag 56 — Boundary enforcement: stated vs structural**
Boundaries that are stated but not structurally enforced tend to erode. Every pragmatic compromise should be tested: is the boundary structural or merely stated? If stated only, design structural enforcement before adopting the compromise.

**Flag 57 — Rights of Nature / Mar Menor precedent**
Mar Menor lagoon (Spain) — first ecosystem in Europe to receive legal rights through 600,000-signature citizen initiative. Classified as "Emergent Commons Guardianship" — closest existing real-world precedent to what the Commons Protocol is designed to produce. Key insight: the tension is whether civic identification can sustain itself as governance once the mobilisation moment has passed. The Commons Protocol addresses exactly this.

Article: "Reframe 1: Rights of Nature and the Many Faces of Guardianship" by Renilde Becqué, The Repatterning Collective, June 2026. Five guardian logics provide vocabulary for answering Randolph's legitimacy questions — Commons Protocol operates in the Emergent Commons model.

Actions queued for v1.0: add Mar Menor to legitimacy section; add recognition vs creation distinction; note Fediverse/Nostr distinction.

**Flag 61 — Adam proposes Aura domain for evidence record evaluation**
Adam's exact message: "I'm rereading some of the sections with an eye to how we might build the infrastructure for the consensus mechanism. I can imagine an Aura domain called 'ecological evidence records' where experts can evaluate their validity. To comply with the 'filter' approach, which I like, there can be a rule in the domain about Aura player locality and proximity when making evaluations. Updraft can fund the development and ongoing maintenance of the protocol, in a way that makes participation open for builders."

Three things this message does:
1. Proposes "ecological evidence records" Aura domain for evaluating credibility of evidence sources — maps directly onto Flag 18 (Approach A vs B). Aura's expert evaluation model with teams and supervisor roles could be exactly the Approach B mechanism without building it from scratch.
2. Proposes locality/proximity rules for Aura evaluators — first concrete technical proposal for implementing the filter pyramid's anti-gaming design rather than just describing it conceptually.
3. Proposes Updraft to fund development and maintenance "in a way that makes participation open for builders" — first time funding the actual signal layer build has been raised as a possibility.

**Scope question raised and answered.** Exchange:

Nik: "I am wondering whether you would envision one Aura domain per question category (ecological, humanitarian, institutional accountability, etc.), or a single broader 'Commons Protocol evidence records' domain that handles all categories under one evaluator framework?"

Adam: "We're moving toward more fluid domains in Aura. So if your niche becomes to evaluate ecological evidence, you will evaluate more of those types of cases (or humanitarian, etc.) Aura players don't have to explicitly register for domains; they just answer questions, and the Aura player app will continue to feed players evaluations they're good at."

This resolves the scope concern cleanly and introduces a third option better than either of the two previously considered. Evaluators are not rigidly assigned to domains — the system learns what each evaluator is good at and feeds them relevant cases accordingly. "Ecological evidence records" as a starting domain name does not preclude humanitarian or other question categories. Specialisation emerges organically from evaluator behaviour rather than being imposed structurally. This is consistent with the protocol's anti-capture principle — no single evaluator pool controls all question categories, but neither does fragmentation into separate siloed domains create inconsistent standards.

Status: scope concern resolved. Aura's fluid domain model is well-suited to the Commons Protocol's multi-category question architecture. Remaining open question: how the evaluator feedback loop handles genuinely novel question categories with no established evaluator niche yet — worth asking Adam in due course but not blocking.

**Flag 65 — GitBook / Starlight presentation format as future documentation model (new)**
The citizen-infra.netlify.app site uses Starlight (Astro-based documentation framework) to present project documentation as a structured, navigable wiki with sidebar navigation, concept pages, toolkit sections, and case study reports. This format is substantially more accessible for non-technical readers than the current GitHub markdown approach.

As the Commons Protocol matures and the audience broadens beyond technical collaborators to institutional, civic, and funding audiences, a similar presentation layer over the existing documentation would significantly improve accessibility. The current GitHub repository remains the canonical home; a Starlight or GitBook front-end could present the same content more invitingly.

Note for later: when the protocol reaches the stage of seeking wider institutional engagement or grant funding, commissioning or building a documentation site in this format should be considered. Not a priority now — the content needs to be stable first.
